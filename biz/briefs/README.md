# briefs — заказы бизнес-сессии технической сессии

Формат: один файл = один заказ. Пишет бизнес-сессия, исполняет технарь в своей сессии.
**Технарь не берёт заказ из головы или из чата — только отсюда.**

Правило заморозки (решение владельца 07.11.2026): движок V2 заморожен. Разрешены **только**
заказы слоя доставки T1–T5. Новые механики, 21-е дело, звук, анимация, сервер, аккаунты, кооп,
сохранение между устройствами, перевод, магазин — не делать, пока не будет строк в `../STATE.md`
типа «письма отправлено: 60, ответов: 3».

| Файл | Что | Часов | Зачем (какой чек) |
|---|---|---|---|
| `T1-forma-iz-konfiguracii.md` | поля формы сдачи и набор исходов читаются из конфигурации дела | 3–6 | чек №1, №2: без этого нельзя спросить «какое требование нарушено» вместо «кто убил» |
| `T2-export-zhurnala.md` | экспорт журнала решений + CSV на группу (**готово в коде 09.11.2026**, ждёт демонстрации постороннему) | 6–8 → уложилось | **главный заказ**: товар = журнал решений, а не балл |
| `T3-brand-config.md` | название/логотип/цвет из конфига | 3 | чек №1: клиент хочет свою фирму на бланке |
| `T4-short-case.md` | короткий формат 20–25 мин, 6–8 материалов, 1–2 зацепки + вариант Б | 10–14 | чек №2: кандидат час не пройдёт |
| `T5-public-build.md` | сборка `public` (без отчёта и ФИО) под Яндекс Игры | 4–6 | чек №4: норматив, тираж, витрина |

Общие для всех заказов ограничения: `js/00-store.js` и `cases/**` не трогать; ключ сейва
`sr.save.v1`; лёгаси-сейвы читаются; после правки — `node tools/check.mjs` → exit 0 (8 гейтов),
потом живой прогон `tools/live/play.cjs` и чтение `tools/live/out/p2.txt` (run.cjs вернёт
`EXIT=0` даже при падении фазы).

Критерий готовности заказа — не «сделано», а «продемонстрировано постороннему за 3 минуты».
