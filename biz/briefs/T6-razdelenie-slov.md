# T6 — разделение слоёв: `corp_game.html` (тимбилдинг) и `Lai_CO.html` (охрана труда)

Заказ: 09.11.2026, формулировка владельца дословно: «Мне не нравится, что дело 21 (которое на
продажу) оно идёт в одном html файле с двадцатью другими делами, которые имеют другое назначение,
раздели их на 2 разных html. То, которое сейчас index html, оно пусть будет corp_game html, а дела
на продажу (типа двадцать первого дела) в отдельном html Lai_CO. В остальном отличий быть не должно».
Уточнения владельца тем же днём: в `Lai_CO.html` **только дело № 21**; `index.html` **удалить совсем**
(«раз и навсегда разделить слои продаж: первые 20 дел — игры для тимбилдинга, 21-е — для охраны труда»).
Часов: 3–4.

## Зачем

Продажное письмо (`../../outreach/PISMO-OT.md`) отправляется ЛПР по охране труда. Сейчас вместе с
демо-делом им приходит 20 дел про убийства — это другой продукт и другой разговор. Разделение
убирает главное возражение «у вас игрушка, а не инструмент» на входе: специалист по ОТ открывает файл,
где есть только его контур.

## Что делаем

- `corp_game.html` — дела № 1–20, каталог и движок без изменений.
- `Lai_CO.html` — только дело № 21 «Особое мнение».
- `index.html` удаляется; в репозитории остаётся ровно два входных файла.
- Отличия между файлами — **только** набор тегов `<script src="cases/…">`, `<title>` и подписи в
  шапке меню. Движок, стили, журнал отчёта (кнопка «Отчёт»), подсказки, доска — идентичны.
- Все инструменты, которые читали `index.html`, переводятся на два файла: `tools/validate.mjs`,
  `tools/smoke.mjs`, `tools/check-dom.mjs` (множество id = объединение обоих файлов, иначе гейт
  деградирует), `tools/check-css.mjs`, `tools/map-case.mjs`, `tools/check-hook.mjs`,
  `tools/check-anon.mjs`, `tools/check-lookalike.mjs`, `tools/pack-demo.mjs` (в архив кладём
  `Lai_CO.html`), `tools/serve.mjs`, `tools/live/*` (адрес страницы).
- Актуальные инструкции правятся (`README.md`, `AGENTS.md`, `docs/HANDOFF.md`, `docs/PIPELINE.md`,
  `docs/PARALLEL.md`, `docs/PLAYBOOK.md`, `docs/OPS.md`, `outreach/REESTR-PISEM.md`). Исторические
  строки приёмки в `docs/PIPELINE.md`, `briefs/case-*.md`, `cases/*/DESIGN.md` не переписываются:
  это летопись.

## Границы

- `js/00-store.js` не трогать; `js/` — только если выяснится, что движок жёстко завязан на имя
  `index.html` (проверить; поразведке 09.11 завязок нет: полка дел строится из `root.CASES`).
- Состав дел в `Lai_CO.html` не расширять без нового заказа.
- Реальных ФИО, названия школы и контура работодателя в файлах не появляется (дело вымышленное,
  обезличивание проверяет `tools/check-anon.mjs`).
- После правок: `node tools/check.mjs` → exit 0 (8 гейтов) и живой прогон
  `node tools/live/probe-report.cjs` → «ошибки страницы: нет».

## Критерий готовности

Два файла открываются двойным щелчком с диска: в `Lai_CO.html` ровно одно дело и работает кнопка
«Отчёт», в `corp_game.html` — 20 дел и ни одного упоминания охраны труда в шапке. `index.html` в
репозитории нет. Демо-борник `dist/demo-ot.zip` пересобран под новый состав, цифры (файлы, байты,
SHA-256) обновлены в `../../outreach/REESTR-PISEM.md`.

## Что НЕ делаем

Разные движки, разные стили, два отдельных репозитория, сборка-склейка, сервер, редирект-заглушка
на месте `index.html`.
