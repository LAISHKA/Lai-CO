# Шаблон дизайна интерфейса

Документ описывает, **как материалы дела превращаются в экран**. Нужен он
полосе, которая переписывает дела под новый интерфейс (первыми — № 1—5), и
мне при приёмке. Сюжетную карту дела описывает `DESIGN.md` внутри дела —
этот файл про другое: про форму.

Менять визуал можно в четырёх файлах: `index.html`, `assets/styles.css`,
`js/10-docs.js`, `js/20-app.js`. Файлы дел вёрстки не содержат и не должны
содержать (§6).

---

## 1. Три канала, через которые дело влияет на экран

| Канал | Что это | Пример |
|---|---|---|
| `kind` | тип материала → «лицо» документа, глиф в списке, лента сверху | `kind: 'ledger'` |
| поля `doc` | структура документа: шапка, реквизиты, таблицы, подпись, штамп | `doc.org`, `doc.table` |
| инлайн `b`/`i`/`u` | единственная разметка, разрешённая в текстах | `'<b>21:40</b>'` |

Всё остальное (цвета, размеры, сетка, темы, печать) решает CSS. Если в
материале нет поля — интерфейс его просто не рисует; выдумывать «красивые»
поля в деле нельзя, их нечем заполнить.

---

## 2. Карта типов материалов

Рендерер выбирает ветку по `kind` (`js/10-docs.js`, `DOCS.render`). Метки и
глифы лежат в `KIND_LABEL` и `KIND_GLYPH` того же файла — менять только там,
в делах ничего не дублируется.

| `kind` | Метка | Глиф | Цвет `--k` | Чем рисуется | Обязательное |
|---|---|---|---|---|---|
| `act` | акт | 📋 | `--k-ink` сине-серый | `paper()` двойная рамка, линия под заголовком | `org`, `num`, `date`, `sign` |
| `doc` | документ | 📄 | `--k-paper` крафт | `paper()` нейтральный лист | `title` |
| `legal` | правовой | `§` | `--k-rule` сиреневый | `paper()` красная полоса сверху, нумерация пунктов | `num`, `body[].h` |
| `order` | приказ | 📜 | `--danger` красный | `paper()` uppercase-заголовок, гриф справа | `org`, `num`, `sign` |
| `ticket` | заявка | 🎫 | `--k-form` зелёный мышиный | `paper()` пунктирная рамка + отрывной корешок | `num`, `date` |
| `table` | таблица | `▦` | `--k-form` | `paper()` с `doc.table`: зебра, горизонтальный скролл | `table.cols`, `table.rows` |
| `ledger` | журнал | `▤` | `--k-form` | `paper()` моноширинный, линовка строками | `table`, `date` |
| `note` | записка | `✎` | `--k-hand` терракота | `paper()` + `doc.hand`: жёлтая бумага, рукописный шрифт, наклон | `body[].p` |
| `talk` | допрос | `❝` | `--k-rule` | `paper()` с `qa`: «В. »/«О. », левая двойная черта | `qa[{q,a}]` |
| `photo` | снимок | 📷 | `--k-lens` синий | `shot()`: рамка 16:9, подпись, `cap` | `img`, `cap`, `alt` |
| `cctv` | видео | 🎥 | `--k-lens` | `shot()`: скан-полосы, OSD, `● REC`, таймкод | `img`, `cam`, `ts` |
| `shot` | экран | 🖥 | `--k-lens` | `shot()` без камеры: снимок интерфейса | `img`, `cap` |
| `email` | письмо | `✉` | `--k-screen` зелёный экран | `email()`: окно клиента, тема, вложения | `subject`, `from`, `to` |
| `chat` | переписка | 💬 | `--k-screen` | `chat()`: пузыри, время, разделитель дней | `msgs[{who,text,time,me}]` |

Правило выбора: если у материала есть `table` — это `table` или `ledger`,
а не `doc`. Если это фотография с места — `photo` со схемой в `img`, а не
`doc` с подписью. Раньше полосы лепили `doc` на 114 материалов из 742;
перерисовка дела как раз и про то, чтобы тип стал честным.

## 3. Контракт полей

`evidence` — массив материалов. У материала: `id`, `cat`, `kind`, `title`,
`where`, `tags`, `keys`, `at`, `after`, `seed`, `doc`. Поля `at` (ЧЧ:ММ),
`after`, `seed`, `tags`/`keys` — игровая механика, дизайн их не трогает.

### 3.1 Бумажный документ (`paper()`)

```js
doc: {
  org: 'ООО «Северный контур»',      // шапка: кто выдал
  title: 'Акт сверки...',             // заголовок
  num: '№ 12-С',                      // номер бланка
  date: '14.02.2026',                 // дата выдачи
  meta: [['Кому', 'В бухгалтерию'], ['Основание', 'договор 4-П']],   // массив пар
  kv:   [['Позиций', '18'], ['Сумма', '340 640 ₽']],                // массив пар
  table: { cols: ['№','Наименование','Кол-во'], rows: [
    ['1','Доска 25×100','40 м³'],                              // строка = массив ячеек
    { cells: ['2','Брус', '12 м³'], cls: 'hi' },               // или объект с ячейками
    { cells: ['—','ИТОГО','340 640 ₽'], cls: 'dim' } ] },      // hi = выделенная, dim = гашёная
  body: [
    { h: 'Результат' },                                        // подзаголовок
    { p: 'Текст абзаца, допустим <b>акцент</b>.' },
    { h: 'Вывод', p: 'Заголовок и абзац в одном блоке — рисуются оба.' },
    { list: ['первый пункт', 'второй'] },
    { quote: 'Цитата из протокола' },
    { note: 'Примечание полями курсива' },
    { hand: true, p: 'Вставка от руки внутри печатного документа.' } ],
  qa: [{ q: 'Вопрос', a: 'Ответ' }],           // talk; у legal тоже рисуется
  sign: { pos: 'Мастер участка', name: 'Кулагин А. В.' },
  stamp: { text: 'ОПЛАЧЕНО', tone: 'ok' },     // tone: 'blue' | 'ok'
  hand: true,                                  // рукописный вид всего листа (note)
  tight: true                                  // плотная вёрстка, мало полей
}
```

В одном блоке `body` можно совмещать ключи — рисуются все, в порядке
`h, p, list, lines, kv, table, quote, note, sign, stamp, html, hand`. Тело
документа допускается и строкой: `body: 'один абзац'` или
`body: ['первая строка', 'вторая']`.

Поля `lines` (массив строк, печатается списком после `body`) и `source`
(печатается в реквизитах как «Источник») — для записей от руки и выписок.

Легаси-алиасы, которые движок терпит, но в новых делах так писать нельзя:
`table.head` (вместо `cols`), `sign.role` (вместо `pos`), `stamp.kind`
(вместо `tone`), `msgs[].from` / `msgs[].at` (вместо `who` / `time`).
Игнорируется и не печатается: `stamp.since`, `sign.text`.

`meta` и `kv` — **массивы пар** (`[['Ключ','Значение'], ...]`). Объект
`{Ключ: 'Значение'}` не отрендерится: `check.mjs` это ловит, `check-case.mjs`
— нет (болячка дела 14).

`cls` у строки таблицы — только на уровне строки. Класс внутри ячейки
печатается как `[object Object]` (дело 20).

### 3.2 Съёмка (`shot()`)

```js
{ id: 'e05', kind: 'cctv', title: 'Камера W-14, холл 23 этажа',
  doc: { img: 'cases/case-01/assets/e05-cam-w14.svg',
         alt: 'выход из 23-14',
         cap: 'Камера W-14, 21:40:12',
         cam: 'W-14 ХОЛЛ-23',
         ts: ['14.02.2026 21:40:12', ['21:40:12', 'выход из 23-14']],
         ph: 'архивная копия, перезапись 21.02' } }   // ph — если картинки нет
```

Схема обязана иметь `viewBox="0 0 1600 900"` (проверяет `check-svg.mjs`).
Картинка без файла не ломает экран: показывается заглушка `.shot-ph` с
текстом `ph`.

`cam` и `ts` — поля верхнего уровня; вложенность `cctv: { cam, ts }` движок
не читает. Элемент `ts` — строка либо пара `[время, событие]`, пара
печатается как `время · событие`. OSD-полоса выходит и у `photo`/`shot`,
если у них задан `cam` или `ts` (метки регистратора, EXIF-время).

### 3.3 Экраны (`email()`, `chat()`)

```js
// email
doc: { bar: 'Входящие — Почта Аргус', from: 's.olbeneva@argus-fin.local',
       to: ['a.torkin@argus-fin.local'], cc: ['ooo.ka@argus-fin.local'],
       subject: 'По сверке', date: '13.02.2026 18:02',
       attach: [['сверка_0212.xlsx', '18 КБ'], 'grandt_svodka.xlsx (1,2 МБ)'],
       body: [ { p: 'абзацы письма' } ], note: 'приписка курьера' }

// chat
doc: { bar: 'Мессенджер, 21:14', msgs: [
  { day: '12 февраля' },
  { who: 'Жена', text: 'ты когда?', time: '21:14' },
  { who: 'Тёркин', text: 'задержусь', time: '21:15', me: true },
  { day: '—', text: 'Сообщения удалены владельцем телефона 10.02.2026' } ],
  subject: 'Отопление в доме 7', from: 'Юркова П. Т.', to: ['Дубровина А. И.'],
  date: '10.02.2026', body: [ { p: 'приложение к переписке' } ],
  note: 'выгрузка с телефона обвиняемой' }
```

`me: true` — реплика «от моего имени» (пузырь справа). Разделитель `{ day }`
с текстом не теряет реплику: если у объекта есть и `day`, и `text`, печатается
и строка дня, и пузырь.

Переписка — не только пузыри: движок принимает `subject`, `from`, `to`, `date`
(печатается шапка как у письма), `meta`, `kv`, `body`, `note`. Так устроены
материалы «переписка с приложением» в делах 07, 09, 11, 12, 14.

`attach` — строка `'имя (размер)'` либо пара `['имя', 'размер']`.
`from`/`to`/`cc` — только строка и массив строк, объекты не поддерживаются.

## 4. Токены: что крутить, если не нравится визуал

`assets/styles.css`, `:root` — типографика и rhythm; `html[data-theme=dark]`
и `html[data-theme=light]` — цвета. Оба набора обязателен: тема переключается
на лету кнопкой и хоткеем `T`.

| Токен | Смысл | Значение по умолчанию |
|---|---|---|
| `--fs-12 … --fs-30` | шкала, 8 шагов, **пол 12px** | 12/13/14/16/18/21/25/30 |
| `--lh-doc` | межстрочный в документах | 1.62 |
| `--measure` | «зеркало» набора | 70ch |
| `--paper-w` | ширина листа документа | 760px |
| `--col-ev` / `--col-board` | колонки списка и доски | 320 / 350 px |
| `--font-ui` | интерфейс | Golos Text (variable 400—700) |
| `--font-doc` | тело документов | PT Serif 400/700/italic |
| `--font-hand` | рукописные записки | системный стек, Caveat не брали |
| `--k-paper/ink/rule/form/hand/lens/screen` | цвета «лиц» типов | §2 |

Шрифты self-hosted в `assets/fonts/` (8 файлов woff2, 226 КБ, подмножества
cyrillic + latin, лицензия OFL). Игрок открывает `index.html` двойным
кликом — шрифты должны грузиться и с `file://`, поэтому пути относительные
(`url('fonts/golos-400-700-normal-cyrillic.woff2')`).

Размеры **нельзя** задавать числом в правилах — только переменной шкалы.
Исключения осознанные: `--ev-pct` (прогресс) и толщины рамок.

## 5. Что добавилось в оболочке (для полос это не editable, но влияет на текст)

- **Сводка дела** (кнопка в топбаре, `G`): прогресс, доли по типам
  материалов, подозреваемые, непрочитанные открытые. Полоса может помочь
  ей честными `kind` — иначе в сводке у дела «114 документов».
- **Плотный список** (`Плотно`) и **фильтр «не прочитано»** — справа от
  поиска по материалам.
- **Режим чтения** (кнопка «Чтение», `R`) — прячет колонки, оставляет лист.
- **Метры в топбаре**: найдено связей и прочитано материалов.
- **Счётчики на вкладках доски**: люди, выводы, время, заметки.

Ничего из этого не читает новых полей в делах — только уже существующие
`kind`, `read`, `found`, `suspects`, `at`.

## 6. Запреты (действуют и после редизайна)

1. В файлах дел **нет** `class=`, `style=`, `<div>`, `<span>`, `<table>`.
   Разметка ровно одна: `<b>`, `<i>`, `<u>` (контракт `js/10-docs.js:3`,
   экранирования нет — HTML в текстах уйдёт на экран как есть).
2. Голос автора в материалах запрещён — три закона дела не отменяются
   дизайном (`check-case.mjs` ловит маркеры, §«читка» в `PIPELINE.md`).
3. Схема (`img`) висит только на `photo`/`cctv`/`shot` (строка 95
   `check-case.mjs`), `viewBox="0 0 1600 900"`, без амперсандов без
   сущности, внутри не должно быть опечаток-«простыней» латиницы в кириллице.
4. Текст подписи/кадра/штампа — **дословно** из документа, без выдуманных
   деталей: интерфейс печатает строки как есть.
5. Новый класс, который полоса хочет «в деле», — неверная идея. Нужен новый
   вид материала — добавляй `kind` в `KIND_LABEL`/`KIND_GLYPH`, карту
   `[data-kind=…]` в CSS и ветку в `render()`.

## 7. Конвейер перерисовки дела (чек-лист № 1—5)

1. `node tools/check-case.mjs case-NN` — снять базовые цифры (материалов,
   связей, SVG, глубина, чтение).
2. Пройти все материалы и привести `kind` к честному (таблица §2). Считать
   глазами: есть таблица → `table`/`ledger`; есть вопрос-ответ → `talk`;
   от руки → `note` + `hand: true`; фото/камера → `photo`/`cctv` + `img`.
3. Дочитать `doc`: `org`/`num`/`date` из шапки документа вынести из тела в
   поля; реквизиты — в `meta` (массив пар); суммы/позиции — в `table`
   (`cols` + `rows`, `cls:'hi'` на значимой строке); подписи — в
   `sign: { pos, name }`; пометки «оплачено/копия» — в `stamp: { text, tone }`,
   `tone` = `blue` или `ok`.
4. Проверить инлайн-акценты: `<b>` только на цифрах/фамилиях/номерах, за
   которые игрок может зацепиться взглядом (их ~1100 на 20 дел).
5. Гейты: `node tools/check-case.mjs case-NN`, `node tools/check.mjs`,
   `node tools/smoke.mjs`, `node tools/check-css.mjs` (смотреть **вывод**,
   он не падает кодом возврата), `node tools/check-svg.mjs`.
6. Съёмка своего дела: `node Temp/opencode/shot-case.cjs case-NN` (или
   правка `after.cjs`), кадр читалки на каждом типе материала — и лист
   до/после.

Ориентир качества: в кадре читалки видно тип материала без подписи (по
«лицу»), строка набора 60—75 знаков, самый мелкий шрифт 12px, в списке —
не менее 16 материалов на экран, в сводке дела нет строчки «документ» на
половине типов.
