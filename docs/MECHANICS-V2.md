## 1. Заказ (суть)

Игрок жалуется: материалы открываются «просто так», если их только пролистать.
Нужен настоящий детектив:

1. новый материал поступает ТОЛЬКО после того, как в уже открытом найденна
   ЗАЦЕПКА и игрок решил, что по ней проверять;
2. новые люди выходят на доску ТОЛЬКО после того, как о них появилось упоминание
   в открытых материалах, в найденных связях или в допросах первых лиц;
3. интерфейс должен выглядеть серьёзнее (экраны, кнопки, допустим перенос блоков);
4. текст нигде не должен «уплывать» (обрезки, переполнения, клип).

## 2. Принятые решения (выбор пользователя, зафиксирован)

| Вопрос | Решение |
|---|---|
| Что такое «найти зацепку» | «Цитата + направление»: игрок выделяет фрагмент в документе и выбирает, что проверять (камеры / пропуска / допросы…). Движок сверяет слова цитаты с тем, куда документ реально ведёт. |
| Доступность людей | «По упоминанию + повестка»: персона появляется, только если её фамилия есть в уже открытом материале; допрос — отдельное действие (повестка), открывается когда зацепка указывает на человека. |
| Клапан против тупика | «Выемка за репутацию + автоклапан»: ходатайство о выемке всего остаётся и сильно бьёт по репутации; тихо, если у материала все предки прочитаны, а словесного мостика в данных нет, материал приходит сам. |
| Экраны | «Сильно: новый каркас»: слева папка дела (входящие / в работе / приобщённые), по центру документ, справа стол следователя с версиями; отдельный экран «Постановление». Риск переделки принятого редизайна принят. |

## 3. Замеренные факты о данных (20 дел, 742 материала)

  Поля `afterLink` в данных НЕТ ни у одного материала (механику на нём не строить).
- `keys` есть у 741 из 742; `after` непустой у 558; корневых (без `after`) — 184, по 5–13 в деле.

  тексте материала напечатано 2581 (54%); в 51 материале — ни одной

- Тупиков после перехода на напечатанный корпус — 0. Тихий автоклапан срабатывает для
  10 материалов (при лексическом мостике по `keys`/`where` их было 3); игрок не видит,

- Фан-аут: 427 предков, детей в среднем 1,73 ({1:241, 2:104, 3:54, 4:16, 5:7, 6:5}).
  У 146 предков несколько детей, из них 67 с одинаковым счётом, поэтому направление надо ВЫБИРАТЬ

- `cat` — готовые человекочитаемые метки направлений (Место, Камеры, Пропуска, Допросы,
  Экспертизы, Деньги, Учёт, Проверки, Морг…). У заблокированных детей топ: Допросы 104,

## 4. Состояние сохранений

`js/00-store.js` НЕ ТРОГАТЬ. Ключ localStorage один: `sr.save.v1`.
`caseState(id)` даёт `{read:[], found:[], suspects:{pid:'watch'|'clear'|'accused'}, notes, hints, clockMs, revealAll, started, verdict}`.
Запись только через `STORE.patchCase(id, st)`.

Новые поля добираются В ДВИЖКЕ сразу после `S.st = STORE.caseState(id)` (в `startCase`),
чтобы легаси-сейвы читались:

- `st.hooks = []` — элемент `{ev: 'e09', quote: '…', dir: 'Камеры', ts: 123}`;
- `st.calls = []` — выданные повестки (ids персон, которых вызвали на допрос);
- `st.seen = {}` — не нужно: для «упомянутых» людей считаем на лету.

## 5. Как работает проверка зацепки (алгоритм, как в коде)

1. Игрок выделяет текст в читалке (≥12 знаков) → появляется кнопка «Взять в разработку»
   (`#hook-bar`, хоткей `J`).
2. Оверлей «Ходатайство о проверке»: цитата + `chips` направлений. Направления = уникальные
   `cat` детей текущего материала (`e.after` содержит текущий id), перемешанные с 2 decoy
   из других `cat` дела (`dummies()`). Порядок и формат счётчика у decoy такие же, как у
   настоящих, — отличить их по интерфейсу нельзя.
3. Игрок выбрал направление → движок берёт СЛОВА направления: пересечение напечатанного
   корпуса предка (`renderedText` = `DOCS.render` → нижний регистр, `ё`→`е`, только
   буквы/цифры) с «адресом» детей (`title` + `where` + `keys` + `short` тегов).
4. Мостик есть, если хотя бы одно такое слово встречается в корпусе предка (стоп-слова общие).
5. Совпало ≥1 ребёнка → хук засчитан (`st.hooks.push({ev, quote, dir, who, ts})`), эти дети
   становятся доступны, в «Протокол хода расследования» уходит строка
   «Основание: <cat> — <title родителя>».
6. Не совпало → «Оснований не вижу» + подсказка искать в тексте фамилию, номер, время.
   Хук НЕ сохраняется, цитата не тратится. Decey обязан давать именно этот отказ.
7. Протоколы допросов (`kind === 'talk'`) из хука НЕ приходят: `grantedIds()` их отсеивает,
   они выдаются только после повестки (`st.calls`) → `pendingTalks()`.
8. Направление остаётся «в работе», пока хоть один материал из него не поступил:
   зацепка с конкретным человеком прикрывает только его материалы
   (`pendingDirections()` не проверяет наличие хука).
9. Прочитанный материал никуда из папки не исчезает: `availableSet()` добавляет все
   `st.read` в открытое.
10. Автоклапан (тихий): материал с непустым `after`, где все предки прочитаны и ни один
    предок не даёт мостика ни в одно направление → открывается сам (10 материалов, §3).
11. `st.revealAll` — «выемка всего дела» за репутацию: открывает всё, в сводке и
    «Постановлении» фиксируется отдельно, штраф в формуле оценки
    (`hints = st.hints + (revealAll ? 3 : 0)`).

## 6. Волны людей

Персона доступна на доске, если выполнено любое:

- `kind === 'victim'` (потерпевшие сразу);
- id персоны есть в `tags` хотя бы одного ПРОЧИТАННОГО материала;
- id персоны есть в `flags` хотя бы одной НАЙДЕННОЙ связи;
- персона в `st.calls` (уже вызвана повесткой);
- `st.revealAll`.

Допрос: у доступной персоны `kind === 'suspect'` — кнопка «Вызвать на допрос»
(`st.calls`), допрос доступен как материал категории `Допросы`, предок которого —
материал с тегом этой персоны. Недоступные персоны не показываются вообще
(не «серые карточки»), но в сводке видна строка «установлено лиц: N, в разработке: M».

## 7. Новый каркас (как сделано)

- Слева — папка дела: корешок `.folder-tab` (`#folder-num` = «ДЕЛО <номер>», `#folder-name`
  = название), три группы в `#ev-list`: «Входящие» (доступные непрочитанные), «В работе»
  (прочитанные, по которым ещё есть незакрытые направления), «Приобщённые» (прочитанные,
  вошедшие в связь или закрытые по всем направлениям). Поиск и фильтр по `cat` сохранены.
- По центру — «стол следователя» (`section.col-reader.desk`: лужа света от лампы +
  текстура) и над листом гриф `#doc-grif`: дело и дата (`#dg-case`), лист дела
  (`#dg-leaf` = «л. д. 16 / 38»), «экз. № 1», плюс штамп `#doc-stamp` по основанию
  приобщения: «ВХОДЯЩИЙ», «ИЗ МАТЕРИАЛОВ ДЕЛА», «ПРИОБЩЕНО ПО ХОДАТАЙСТВУ»
  (класс `stamp-hook`), «ПРОТОКОЛ ДОПРОСА».
- Справа — стол следователя: вкладки «Люди», «Связи», «Ход» (`renderProtocol()`,
  список `st.protocol`), «Хронология», «Заметки». Люди выходят волнами
  (см. § 6 в `docs/PIPELINE.md`-нумерации этого файла — §6), повестка — кнопка
  `button.summon[data-act="summon"]`.
- Экран «Постановление» — отдельный view `#view-verdict` (`#verdict-scroll` >
  `.postan#verdict-body`), а не оверлей: шапка бланка (`postanHead`), поля версии
  (`.pa-fields`), подписи (`.pa-sign`), кнопки `[data-vact]` = `back` / `send` /
  `print` / `again` / `menu`. `Esc` с формы возвращает к материалам, с итога — нет.
  Печать бланка описана в секции 16.5 `assets/styles.css`.

### Про многоточие на карточке дела

`logline` (аннотация, до 342 знаков, 20 дел) на титуле обрезается до трёх строк —
`.cc-log` с `-webkit-line-clamp: 3`. Это единственный разрешённый многоточный обрыв в движке: полный текст аннотации игрок читает в брифинге дела
(`.ov-log`, выводится при первом открытии). Детектор `sweep.cjs` поэтому считает
`-webkit-line-clamp` и `text-overflow: ellipsis` штатными и не поднимает по ним
замечаний — но при любой новой обрезке текста надо проверить, что полный текст
доступен где-то ещё.
