Файл-состояние. Если сессия оборвалась — начинать отсюда: здесь записано, какая
волна идёт, что уже лежит на диске и как принять дело.

**Если открывается НОВАЯ сессия — читать сначала `docs/HANDOFF.md`** (там проверенное
состояние, порядок приёмки, промпт полосы, что не работает и болячки среды).

## Правила очереди

1. Волна = три дела, каждое делает своя параллельная полоса (`fixer`, background).
2. Полоса работает только в `cases-wip/case-NN/` и `Temp\opencode\laneNN`
   (подробности — `docs/PARALLEL.md`).
3. Следующая волна стартует только после зелёного гейта по всем делам текущей.
4. Приёмку (перенос в `cases/`, правки входных html — `corp_game.html`/`Lai_CO.html`,
   `README.md`, `docs/*`) веду
   один, последовательно, по одному делу.

## Как определить состояние полосы без интерфейса

`task_status` на этом хосте недостоверен (`session-status capability unavailable`).
Живой индикатор — время записи файлов:

```powershell
Get-ChildItem cases-wip\case-09 -Recurse -File | Sort-Object LastWriteTime -Descending |
  Select-Object -First 4 Length, LastWriteTime, Name
```

Если ПОСЛЕДНИЙ файл (включая схемы в `assets/` — полоса может писать их, не трогая
`.js`) старше ~40 минут и `07-links.js`/`08-final.js` ещё скелеты
(240—503 байта) — полоса сдохла: поднимать через `task_revive` с точным списком
пустых файлов. Порог 40, а не 25: замеры волны 5 показали интервалы записи 15—36
минут на одном файле, более короткий порог хоронит живые полосы. Возобновление через
`subagent(sessionID=...)` не работает
(«unreconciled»); новый запуск полосы создаёт дубликат, этого избегать.
