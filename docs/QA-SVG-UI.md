# Лупа схемы (UI) — что сделано по жалобе «текст ужасно ужат»

Замер: 10.11.2026. Полоса: только интерфейс. Данные дел, `js/00-store.js`,
`js/10-docs.js`, `js/17-candidates.js`, `tools/**` не тронуты.

Методика кеглей и приговор «кеглями не лечится» — `docs/QA-SVG-READABILITY.md`
(§1, §3). Здесь — то, что дала лупа, в пикселях.

## 1. Механика жалобы

Схема живёт в холсте `viewBox="0 0 1600 900"` (все 107 файлов). Читалка сжимает её
до ширины колонки. Замер в живом браузере, окно 1600×900: `#reader` = 920 px,
картинка = **886 px** (`QA-SVG-READABILITY` даёт 881 px — те же ноги, расхождение
в 5 px, мерили разными способами). Значит `k = 886 / 1600 = 0,55`, и подпись в
12 условных единиц печатается **6,6 px**. Пороги: 9 px — ниже нельзя, 12 px —
нормально.

Лечится вторым экраном: клик по съёмке кладёт схему в штатный оверлей на всю
ширину окна, где `k = 1` при окне 1600 px и выше.

## 2. Как пользоваться

Подсказка на экране (одна строка, 12 px, цвет `--fg-mute`):
«колесо с Ctrl — зум, перетаскивание — сдвиг, двойной клик — приблизить, Esc — закрыть».

| действие | что происходит | замерено |
|---|---|---|
| клик по съёмке / `Enter` / `Space` на ней | лупа открыта, кадр по центру | фокус на `.lens-stage` |
| `+` / `−` (и кнопки `+`/`−`) | шаг ×1,25 | 4 шага → 2,44× (кадр 3906 px) |
| потолок и пол | `LENS_MIN=1`, `LENS_MAX=6` | 6× → кадр 9600 px |
| `1` / «1:1» | одна условная единица схемы = один экранник | 1600 px при любом окне |
| `0` / «по ширине» | 1×, вся ширина окна | 1600 px при окне 1600 |
| двойной клик в точку | ×2 к месту под курсором | 1600 → 3200 px, дробь точки 0,25/0,318 не ушла |
| `Ctrl` + колесо | зум к курсору, страница не масштабируется | 1600 → 2000 (×1,25) → 1600; без `Ctrl` — no-op |
| перетаскивание мышью / пальцем | сдвиг кадра | (−220,−110) и (−260,−150) — один в один, `touch-action: none` |
| стрелки | сдвиг, с зажимом по краям кадра | правый край 1600 = край стекла, левый 0 = 0 |
| `Esc`, клик мимо, «Закрыть» | лупа закрыта | фокус вернулся на картинку, читалка прокручивается (`scrollTop` 126) |

Зажм сдвига: `|(rendered − stage) / 2|`, уехать в чёрное нельзя.

Реализация: `js/20-app.js`, секция «ЛЕНЦА: СХЕМА КРУПНЫМ ПЛАНОМ» (`openLens`,
`lensWire`, `lensZoom`, `lensStep`, `lensFit`, `lensNative`,
`lensDrag`, `lensPaint`, `onLensResize`); стили — `.overlay.lens-open`,
`.overlay-inner.lens`, `.lens-head`, `.lens-title`, `.lens-tools`, `.lens-stage`,
`.lens-hint` в `assets/styles.css` (секция 15Ж).

Картинка в лупу **клонируется** (`cloneNode`), разметку `js/10-docs.js` не меняли:
печать документов и все 21 дело ведут себя как раньше.

## 3. Кегль: было / стало

`px = кегль_в_единицах × (ширина_рендера / 1600)`. Колонка 886 px → лупа 1× при
окне 1600 px (это же и «1:1»).

| схема | узлов | кегль min/мед, у.е. | было, px | стало, px |
|---|---|---|---|---|
| case-21/e08 `camera-vestibule.svg` | 37 | 13 / 15 | 7,2 / 8,31 | 13 / 15 |
| case-08/e16 `e16-cameras.svg` | 69 | 12 / 12 | 6,65 / 6,65 | 12 / 12 |
| case-15/e02 `e02-polygon-plan.svg` | 48 | 11 / 13 | 6,09 / 7,2 | 11 / 13 |
| case-10/e28 `04-corridor-bank.svg` | 43 | 11 / 13 | 6,09 / 7,2 | 11 / 13 |
| case-13/e10 `03-ekran-arm.svg` | 67 | 11 / 15 | 6,09 / 8,31 | 11 / 15 |

**Медиана медиан 7,2 px → 13 px** (порог ≥12 px). Худший узел из пяти: 6,09 → 11 px
при 1×; при 2,44× медиана `e08` = 36,6 px, при 6× = 90 px.

Корпус целиком (104 файла из 107, у 3 файлов нет текстовых узлов с `font-size`):

| метрика | колонка 886 px | лупа 1× = 1600 px |
|---|---|---|
| медиана файловых медиан | 8,86 px | **16 px** |
| медиана файловых минимумов | 7,75 px | 14 px |
| самый мелкий кегль в корпусе | 5,54 px | 10 px |
| файлов с медианой ≥ 12 px | 0 из 104 | **104 из 104** |
| файлов, где самый мелкий кегль ≥ 12 px | 0 | 98 из 104 |
| файлов с узлом мельче 9 px | 93 | **0** |

Чтобы медиана самого плотного файла дала 12 px, нужно 1,81×; по медиане корпуса —
1,35×. То есть один шаг `+` закрывает и это.

## 4. Ширина окна решает всё (границы применимости)

1× = ширина окна, поэтому:

| окно | кадр при 1× | медиана корпуса (16 у.е.) | вывод |
|---|---|---|---|
| 1600 px | 1600 px | 16 px | норма |
| 1280 px | 1280 px | 12,8 px (у `e08` мерено 12 px) | норма; `e16-cameras` (12 у.е.) — 9,6 px, жмём «1:1» → 15 px |
| 860 px | 850 px | 8,5 px | нужен зум: «1:1» (1600 px) + сдвиг |
| 420 px | 410 px | 4,1 px | только зум; окно 1600×900 — целевое |

Формула «читаемого» стартового зума (§5.1 `QA-SVG-READABILITY`):
`z = ПОРОГ × 1600 / (кегль_медианы × ширина_окна)`; с порогом 12 px и медианой
корпуса 16 у.е. это `1200 / W` — 1,0× при 1200 px и 2,9× при 420 px. С порогом
13 px, который взяла соседняя полоса, — `1300 / W`. См. §8.2: в дерево эта
формула уже легла, но после этого замера.

Узкое окно ломает не лупу, а топбар: при 420 px документ переполняется на 337 px
(`div.topbar-tools` → `span.stat`, `button.btn`) **с закрытой лупой и на стартовом
меню** — это было до правки. Сама лупа даёт 0 переполнения по горизонтали при
1600 / 1280 / 860 / 420 px; при ≤860 px шапка переносится на две строки
(`.lens-head { flex-wrap: wrap }`), подсказка тоже — это единственное, что портит
вид на телефоне.

## 5. Вкус: числа, не ощущения

Новых цветов **ноль**. Использовано: `var(--bg)`, `var(--bg-2)`, `var(--line)`,
`var(--fg-mute)`, `var(--fs-12)`, `var(--fs-14)`, и `#05070a` — тот же фон, что у
бокса съёмки в читалке (`.shot-img`), поэтому схема не «вспыхивает» при открытии.
Градиентов нет.

Замер computed-style, обе темы, 1600×900:

| что | значение |
|---|---|
| тень кадра / стекла / шапки / подсказки | `none` — нигде |
| `.overlay-inner.lens` | тень `none`, рамка `0px none`, радиус `0px`, размер 1600×900 |
| базовый `.overlay-inner` (обычные попапы) | не тронут: тень `0 18px 44px rgba(0,0,0,.55)` (dark) / `0 14px 34px rgba(72,60,34,.18)` (light), радиус 14 px, поля подложки 20 px |
| подложка лупы | `padding: 0`, `place-items: stretch` |
| светлая тема | шапка `rgb(246,242,233)`, граница `rgb(210,201,182)`, заголовок `rgb(31,36,48)`, подсказка `rgb(138,143,154)` |
| служебные полосы | 79 px из 900 (шапка 48 + подсказка 30) = 8,8 % экрана |
| кнопки | штатные `.mini` (26 px, `--bg-2`, радиус 4 px) и `.btn.ghost.sm` (31 px) — новых классов кнопок нет |

**Осознанное отступление от `docs/TASTE-BAR.md`** («оверлеи и попапы: max-width
900px, radius 10px»): лупа — 100 % окна и радиус 0. Карточка на 900 px вернула бы
ровно ту же жалобу, ради которой она сделана. Для всех остальных окон правила
вкуса не менялись.

## 6. Регрессия: что осталось как было

* Съёмка в материале: `object-fit: cover`, `aspect-ratio` 16/9, та же ширина
  886 px. Единственное видимое изменение в читалке — `cursor: zoom-in` и
  `title`/`aria-label` у картинки (навешиваются обработчиком, не разметкой).
* Печать: `#overlay` был `display: grid` на экране → `none` на печати; явно
  закрыт и полноэкранный вариант (`@media print { .overlay.lens-open { display: none } }`).
  Кадр по-прежнему печатается внутри материала.
* Выделение текста не перехвачено: перетаскивание больше 6 px лупу не открывает
  (проверено на `figcaption.shot-cap` — лупа закрыта).
* Стрелки под лупой не перелистывают читалку: 160 нажатий → материал «6/6»,
  заголовок тот же, `scrollTop` 0.
* Слушатели висят на лупе, не на `document` (кроме штатного `Esc` оверлея);
  `root.addEventListener('resize', …)` снимается в `onClose`.
* Новых `id` нет → `corp_game.html` и `Lai_CO.html` не менялись;
  `check-dom` как показывал 57 id, так и показывает.
* Ошибок страницы за весь прогон: **0**.

## 8. Что не сделано и с чем надо свериться

1. **Буква TASTE-BAR §1.1 требует 12 px «без лупы».** По корпусу это невозможно
   без перерисовки схем (`QA-SVG-READABILITY` §3), поэтому сделана лупа. Чтобы
   закрыть критерий буквально, нужен подъём ключевых кеглей в худших ~12 схемах
   (`QA-SVG-READABILITY` §5.2) — это не UI и не эта полоса.
2. **Стартовый зум и кратность в шапке — дописаны и ПЕРЕСНЯТЫ живьём (вечер
   10.11).** Дефолт лупы теперь `max(читаемый, закрыть стекло)`, `LENS_FS`
   хранит медиану САМОЙ МЕЛКОЙ схемы дела (не среднюю по делу: с ней дело № 8
   печатало 11,1 px при 630 px), № 16 понижено 14 → 13. Калькуляция одна:
   `px = 13 × медиана / LENS_FS`, то есть 13 px при любом окне. Замер в браузере,
   `case-08/e16-cameras.svg` (69 текстовых узлов, min/мед = 12 у.е.), один клик по
   схеме, дальше без нажатий, обе темы, ошибок страницы 0:

   | окно | без лупы (кадр → медиана) | лупа | кадр → медиана | узлов <12 px | <9 px |
   |---|---|---|---|---|---|
   | 1600 px | 886 px → 6,65 px | 1,1× | 1733 px → **13,0 px** | 0 % | 0 % |
   | 881 px | 549 px → 4,12 px | 2,0× | 1733 px → **13,0 px** | 0 % | 0 % |
   | 630 px | 586 px → 4,39 px | 2,8× | 1734 px → **13,0 px** | 0 % | 0 % |

   Это закрывает §5.1 `QA-SVG-READABILITY` («читаемо без единого нажатия»). §4
   ниже описывает поведение при явном `1×` и остаётся справочным: он про то, что
   игрок видит, если сам нажмёт «по ширине».
3. **Скрипт проверки живёт в `Temp`**, а не в `tools/live/` (полоса `tools/**`
   была закрыта): `f3-lens.cjs` (кегли + все жесты + обе темы + печать),
   `f3-look.cjs` (computed-style), `f3-narrow.cjs` (переполнение),
   `f3-corp.cjs` (корпус 104 файлов), `f3-shadow.cjs` (каскад лупы). Прогон —
   headless Chrome на своём профиле и порту; `tools/live/play.cjs`, `sweep.cjs`
   и `gate.cjs` **не запускались**: они делают `taskkill chrome.exe` и убили бы
   открытую браузерную сессию владельца.
4. **Скриншоты есть, но глаза у проверяющего другие.** Кадры лежат в
   `%TEMP%\opencode\f3-*.png`; вывод этой модели — числа. Живой просмотр
   «красиво/некрасиво» остаётся за владельцем.

## 9. Попутный дефект: при ≤1180 px панель «Доска» глушила клик по схеме

Пересъёмка §8.2 не открывала лупу при окне 881 px, и это оказался не дефект лупы.
При `max-width: 1180px` колонка доски (`styles.css:1863`) — `position: absolute`,
`width: min(400px, 92vw)`, `z-index: 20`, то есть выезжающая панель поверх читалки.
А `openCase` вызывает `switchTab('persons')`, и тот при том же окне сам вешает
`board-open` (`20-app.js:1086`). Итог: открываешь дело — доска уже сверху, в
читалке остаётся полоса ~193 px из 881, а клик по центру схемы уходит в карточку
лица (`elementFromPoint` на середине картинки даёт `DIV.p-name`). Лупа не
открывалась вообще, и никакие кегли тут не при чём.

Лечение — одна строка в `openEvidence`: открыл документ — снять `board-open`, если
экран в режиме панели. Доска остаётся доступной кнопкой «Доска» и клавишей `B`;
при находке связи она открывается по-прежнему (`switchTab('clues')`), там это нужно.
После правки лупа открывается одним кликом во всех трёх окнах (таблица в §8.2).
