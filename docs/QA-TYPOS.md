# Гейт опечаток (`tools/check-typos.mjs`)

Снимок цифр: 10.11.2026, после полосы G1 (тексты дел) и моих правок стыков.
Актуальные числа всегда даёт сама команда, §9.

## 1. Зачем, и чем отличается от `check-lookalike.mjs`

`check-lookalike.mjs` ловит артефакты модели: иероглифы и латинское слово между
двумя кириллическими. Он был в гейте и раньше.

`check-typos.mjs` ловит механический брак вёрстки текста: подмена букв внутри
слова (кириллица + латиница — «рaзмер»), пробельный брак, кавычки, незакрытые
инлайн-теги, повтор слова, битую кодировку и **склейку строк на стыке
конкатенации**. Именно последний класс дал в деле № 21 пятьдесят восемь
испорченных стыков вида «правша.Одиннадцатый год», и ни одна прежняя проверка
его не видела.

## 2. Как подключено

Одиннадцать шагов в `node tools/check.mjs`; наш шаг — «опечатки в текстах дел»:

```
['опечатки в текстах дел', 'tools/check-typos.mjs', ['--gate']]
```

В гейт встроен **только режим `--gate`**, и в нём проверяются **только `cases/`**
(данные дел, которые игрок читает). Порог падения — `error` + `warn`; `info` не
валит. Без `--gate` тулза работает как отчёт по всему репозиторию (`cases`, `js`,
`assets/styles.css`, оба входа, `docs`, `biz`, `outreach`, `README.md`,
`AGENTS.md`) и падает только на `error` — правки движка и деловых текстов этим
не блокируются, вывод читается глазами.

## 3. Метод

* **Данные дел.** Восемь файлов дела загружаются так же, как в
  `tools/validate.mjs`: stub-`window`, `registerCase`, обход рекурссией по всем
  полям. Поэтому видно **реальный склеенный текст**, а не куски из исходника:
  `'правша.' + 'Одиннадцатый'` придёт как `правша.Одиннадцатый`. Файл и строка
  находки добираются поиском фрагмента по файлам дела.
* **`js/*.js`** — строковые литералы и комментарии (мини-сканер исходника).
* **`*.md`** — построчно, с пропуском ``` блоков и инлайнового `code`.
* **`*.css`, `*.html`** — только комментарии и текстовые узлы, теги маскируются.

Перед правилами текст маскируется (`░`) в местах, где проверка бессмысленна:
HTML-сущности, теги, числа с единицами, URL, имена файлов, инлайн-код.

## 4. Правила

| код | уровень | что ловит |
|---|---|---|
| `mixed-alpha` | error | кириллица и латиница в одном слове |
| `mojibake` | error | битая кодировка (`Ã¯`, `â€`) |
| `unbalanced-quotes` | error | несовпавшиеся `«` и `»` |
| `unclosed-inline` | error | незакрытый `b/i/em/strong/span/u/s/sup/sub` |
| `glue-concat` | error | стык конкатенации без пробела (§5) |
| `double-space` | warn | два пробела между словами |
| `space-before-punct` | warn | пробел перед `, . : ; ! ? )` |
| `no-space-after` | warn | нет пробела после `, ; : .` |
| `repeat-word` | warn | одно слово подряд (с реестром легальных) |
| `straight-quote` | warn | кавычка-лапка `"` вместо `«»` |
| `thin-space` | warn | тонкий/неразрывный пробел в русском тексте |
| `dash` | warn | « - » вместо дефиса |
| `lower-after-dot` | info | строчная буква после «. » |

## 5. `glue-concat` — правило уровня исходника

Его не хватает по данным: `no-space-after` смотрит на склеенный текст и
не отличает пропущенный пробел от авторского стиля, а «слова склеены без
разделителя» и вовсе не ловит нигде. Правило читает `cases/case-NN/*.js`
построчно и ищет стык:

```
'…какой-то текст' +
'продолжение без пробела…'
```

Ошибка, если перед закрывающей кавычкой нет пробела, а следующая часть
начинается с буквы. Не ошибка (проверено глазами на всех 21 деле, ложных нет):

* хвост предыдущей части кончается на перенос `\n` — намеренный абзац или
  построчная записка (`case-01/03-evidence.js`, `case-14/02-evidence.js`);
* дефисный перенос: «патолого-» + «анатома», «судебно-» + «медицинские»;
* инициалы: `[А-ЯЁ].` на конце и заглавная в начале;
* номер (`№`) в предыдущей части;
* следующая часть начинается не с буквы.

Находки печатаются с `файл:строка` и входят в код выхода. `allowlist` на них не
распространяется: такой стык — всегда правка в исходнике дела.

## 7. Что гейт НЕ ловит (читать до того, как успокоиться на зелёном)

* Смысл. `reveals` может быть грамматически чистым и фактически неверным —
  это проверяется только чтением дела и `tools/map-case.mjs`.
* Орфографию без следов: «превед», «излищнение», лишний падеж.
* Кавычки, раскрытые по разные стороны разных полей (`«` в одном `<p>`, `»` в
  другом) — на уровне юнита всё сходится.
* Пунктуацию и стиль: лишняя запятая, канцелярит, повторы мыслей.
* Брак внутри одного длинного литерала, если он не даёт формального признака.
* Всё, что видно только в браузере: переполнение, наезд подписей на схемах —
  это `tools/live/sweep.cjs` и `tools/svg-audit.mjs`.

## 8. Allowlist (ложные срабатывания)

`tools/typos-allowlist.txt`, формат — табуляция между полями:

```
код   файл   подстрока пути поля   причина
```

Ключ **структурный**, а не строчный: поле `where` у находки выглядит как
`поле evidence[27].doc.kv[2][0]` и не зависит от того, на какой строке лежит
текст после правок дела. Поэтому allowlist не молчит после того, как текст
сдвинулся, и не проглатывает новую опечатку в другом материале.

## 9. Как запускать и что делать при красном

```
cmd /c "node tools/check-typos.mjs --gate > %TEMP%\typos.txt 2>&1"   # как в гейте
cmd /c "node tools/check-typos.mjs --budget 0 > %TEMP%\typos.txt 2>&1"  # счётчики по всему репо
cmd /c "node tools/check-typos.mjs --paths cases/case-09 --budget 5 > %TEMP%\typos.txt 2>&1"
```

Кириллица в консоли PowerShell ломается — читать файлом.

При красном шаге: открыть вывод, для каждой находки прочитать 10–15 строк
контекста и решить — брак (чинить в `cases/`) или ложное (строка в allowlist с
причиной). Править массово по regex запрещено: часть «повторов слов» — таблицы и
прямая речь.
